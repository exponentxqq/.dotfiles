## 附：差异收敛六步判据（自 SKILL.md §五 外移）

两条规划线都回执后，主会话做差异收敛——六步，一步不省；其中**第 4 步的提问环节加载并遵循 `grill-me` skill 的设计树/前沿分轮方法**（方法来自该 skill；**问答由主会话执行**——子代理自己不能提问，规划线与复算线的问题经第四节中转协议上浮后**并入同一套提问**，不再另开通道）：

1. **交叉比对**：逐字段（7 字段逐一）对齐 `line-a.md` 与 `line-b.md`，把每一条内容归入三类：
   - **共识**：两线都提出且结论一致 → 直接采信。
   - **分歧**：两线都提出但结论不同 → 交第 2、3 步裁定。
   - **单边遗漏**：只在一条线出现 → **遗漏信号**。SHALL **逐项核验**：成立则纳入落档，不成立则写明理由后丢弃；**绝不因"只有一条线提出"而丢弃**。
2. **自行裁定**：能从代码、规范或只读命令查证的分歧，**主会话自己查证**（必要时派只读子代理），记录裁定依据（查了什么、结论是什么）；**不得转为提问**。
3. **分歧复算（第三条线）**：仅对「影响方案走向**且**无法从环境查证」的分歧，派第三条 **fresh** 子代理（`panel` 路由）复算。
   - 复算子代理**不以任何既有草案为输入**：只给**分歧点陈述 + 需求原文**，要求它给出**独立判断 + 理由 + 反例**。
   - **三线对照**：两线一致或 2:1 → 形成结论、依据与置信说明；三条互不相同 → 升级为**用户决策项**。
   - **默认每次流程最多复算 3 个分歧点**（超出时按影响面排序取前 3），其余升级为决策项。
4. **按 `grill-me` 方法问决策项**（加载并遵循 `grill-me` skill；本 workflow 只把「怎么问」交给它，其余步骤不变）：
   - **映射为设计树**：把全部待决项——规划线「待决问题」节上浮的、复算后仍存的分歧、单边项核验后仍待定的取舍——映射为一棵**设计树**：**节点即决策，边即依赖**（某决策的答案是否会改变另一决策的前提 / 选项）。
   - **只问前沿**：**前沿** = 前置决策已定、现在就能问而不必猜未听到答案的那批问题。**仅前沿问题进本轮**；**依赖未决答案的问题留到后续轮次，不得同轮抛出**。
   - **每轮 ≤5 问**：前沿更大时先问**承重最大**的（挂靠决策最多的那些），其余自然成为下一轮前沿；每题**编号**并**附推荐答案**，措辞使「是 / 同意」即等于接受该推荐答案，同时标注推荐来源（共识 / 复算 / 子代理建议）。
   - **事实自行查证**：需要环境事实（文件、代码、规范、命令输出）时自己读代码、读规范、跑只读命令，必要时派只读子代理去查——**不向用户索取可查证的事实**（与第 2 步同一原则）；查证未回期间只有其下游问题等待，**其余前沿照问**（事实未定即前置未定）。
   - **答完重算前沿**：用户答完一轮，前置随之落定，**重新计算前沿**再给下一轮。
   - **收敛结束条件**：**前沿为空**，或用户**明确确认「已达成共识 / 可以落档」**；用户确认前不得据此行动（尤其不得落档）。
   - **答复回送**：需要子代理据此继续的答复，按引擎**回送同一成员或接续重派**（第四节中转协议）；上浮项只并入本设计树，不另开问答通道。
   - **不因此改变的部分**：本 workflow 的**三分类（共识 / 分歧 / 单边遗漏）、自行裁定、第三线复算与 `diff-matrix.md` 留痕一概不变**——`grill-me` 只接管「怎么问」，待决项的**来源、裁定与复算逻辑**仍按第 1–3 步执行。
5. **记录**：单边项核验结果、裁定依据、复算结论与**设计树/前沿分轮的问答**（问题、答复、是否仍待决）**全部写入** `/tmp/spec-flow/<change>/diff-matrix.md`（三分类矩阵 + 设计树与前沿分轮记录 + 依据 + 结论），它是阶段 2 落档的输入之一。
6. **收敛结束**：**前沿为空**（设计树每条分支都走到、没有被静默假设的项），或用户在**明确确认「已达成共识 / 够了，可以落档」**后结束；确认之前不得据提问结果行动（不得落档）。仍未答的项**不得静默假设**——写进落档 design 的「未决/后续」并在落档摘要里列出。

用提问工具（单选/多选 + 推荐项）**按前沿分轮**问；**只问决策，不问事实**。
