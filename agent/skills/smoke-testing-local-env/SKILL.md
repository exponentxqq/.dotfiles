# 本地环境端到端冒烟验证

## 概述

拓扑固定为：**宿主机 docker 化开发环境（跑服务）+ dsh 容器（跑 agent 与浏览器）**。
规程固定为：**环境侦察 → 零侵入链路 → 数据准备 → 浏览器执行 → 三层证据 → 归档收尾**。

产出必须能回答三个问题：**功能真的跑通了吗？证据在哪？哪些是观察项而非缺陷？**

配套文件：

| 文件 | 用途 |
| --- | --- |
| [reference.md](reference.md) | 完整操作手册：命令模板、浏览器配方、陷阱全表 |
| [project-profile-template.md](project-profile-template.md) | 项目画像模板（复制到各项目仓填写） |
| [scripts/recon.sh](scripts/recon.sh) | 环境侦察：宿主服务可达性三态判定 |
| [scripts/tcp-bridge.mjs](scripts/tcp-bridge.mjs) | 跨容器 TCP 桥接（浏览器在容器、服务在宿主时） |

## 技能目录定位

本技能在容器与宿主是同形路径 **`~/.agents/skills/smoke-testing-local-env/`**（skctl 聚合层 symlink 指向 dotfiles 实体；容器内为只读挂载，脚本可直接读取执行）。本文所有命令中的脚本路径均按此解析。

## MCP 依赖与降级

默认依赖两个 MCP：**chrome-devtools**（浏览器驱动）与 **dbx**（数据库查询）。任一未接入时按下列方式降级，并在报告"测试环境"节声明证据缺口：

| 缺失 | 降级方式 | 证据缺口 |
| --- | --- | --- |
| chrome-devtools | curl 直接打接口 + 请用户在宿主浏览器配合截图 | UI 层证据缺失 |
| dbx | 请用户在宿主执行 SQL 回传结果 | 持久层证据缺失 |

降级结论必须标注**"非全链路验证"**，不得按三层证据口径判定通过。

## 何时使用

- 用户要求"跑一遍 / 冒烟 / 端到端验证 / 验收"某个刚实现的功能
- 需要判断"页面提示成功"是否等于"数据真的落库"
- 需要从容器内访问宿主服务（后端、前端 dev server、DB、对象存储）
- 需要真机走浏览器流程（上传、字典联动、状态机流转、跨页跳转）

## 何时不使用

- 纯单测/编译/静态检查——直接跑对应命令即可
- 只审代码、服务未启动——用 `requesting-code-review`
- 交付物文案与截图审核——用 `reviewing-deliverables`

## 第一原则：先读项目画像

**通用规程在技能里，项目专属事实在项目仓的项目画像里。** 开始前先找项目仓的 `docs/smoke-test-profile.md`：

- 有 → 按画像里的端口、入口、账号、MOCK 开关执行
- 无 → 用 `scripts/recon.sh` 采集事实现场补齐，并建议落盘到项目仓（模板见 [project-profile-template.md](project-profile-template.md)）

**不要把项目专属事实写进本技能**，否则技能会随项目漂移、多处维护。

## 核心原则

1. **环境事实先行**——端口、进程、浏览器位置、网络路径先测清楚再谈用例；多数"功能不通"实为链路错位。
2. **零侵入**——不改宿主项目配置，不在容器内起第二套服务或语言环境；跨容器只用临时 TCP 转发。
3. **三层证据**——UI 状态 + 网络请求 + 持久化/外部副作用，三层一致才判通过。
4. **正例基准先行**——先跑通一条正例再铺负例矩阵；负例全错时优先怀疑基准 payload。
5. **真实请求体是契约的最终解释**——契约可能滞后，以浏览器抓到的真实 body 为准。
6. **观察项 ≠ 缺陷**——非阻断异常单列，写明影响面与归属，不混入结论。

## 流程

### 阶段 1　环境侦察（不可跳过）

**目标**：把"我以为"换成"实测"。

1. 读项目画像，确认被测服务、入口、账号
2. `scripts/recon.sh <宿主IP> <端口...>` 判定宿主服务可达性（三态，见 reference §2.1）
3. 判定浏览器位置：浏览器在**容器内**，`localhost:<port>` 指容器自身而非宿主
4. 确认外部依赖是真实组件还是 MOCK，以及 MOCK 的产出规律
5. 确认 DB 可达（dbx 连接、库名、关键表）
6. 宿主服务日志在**归属方终端**，容器内不可见——需要时向用户索取，不要假设能看到

**卡点**：TCP 通但 HTTP `000` / `Connection reset by peer` = 端口被残留转发占用。不要改配置，换路径或稍后重试。

### 阶段 2　零侵入链路

- 前端 `apiBase` 是**绝对 URL** 且指向 `localhost` 时，在**容器侧**起桥接：
  `node ~/.agents/skills/smoke-testing-local-env/scripts/tcp-bridge.mjs <端口> <宿主IP> <端口>`，再验证健康路径
- 同源代理型前端（后端 CORS 关闭）走它自己的 dev proxy，不要绕过
- 红线清单见 reference §2.5：不改宿主配置、不在容器内构建、不起第二套服务

### 阶段 3　数据准备

- 需要验证码/一次性凭据：**查库取真值，禁止心算**
- 需要校验位的字段（身份证、统一社会信用代码等）：按算法生成
- 密码类字段：先读复杂度规则再定值
- 注意限流窗口，整轮验证尽量复用同一账号
- 数据带可检索前缀（如 `冒烟`），记录全部主键与外部对象 key

### 阶段 4　浏览器执行

- `take_snapshot` 优先；自定义组件选项抓不到时回落 `role="option"` DOM 查询
- **一次 `evaluate_script` 只做一个交互动作**（响应式异步，连续点击只有最后一个生效）
- 瞬时提示（3 秒消失）必须**在触发前**预埋 MutationObserver
- 上传用 `upload_file` 注入真实文件：正例 + 超限/类型/数量反例
- 网络层用 `list_network_requests` + `get_network_request` 导出真实请求体
- 等待用 `wait_for` 收口，不要 sleep 轮询；页面被 dev 热重载整页刷新时，重新取态再断言（reference §4.10）

### 阶段 5　三层证据

| 层 | 证据 |
| --- | --- |
| UI | 页面文本/状态 + 截图 |
| 网络 | 端点、状态码、请求/响应体 |
| 持久化 | 落库行（含状态机字段）、外部对象存在性 |

"页面提示成功"或"接口 200"单独都不构成通过。

时间类字段（截止时间、发表时间等）按**项目画像 §0 的业务时区**解读与断言，警惕 UTC 截断与跨天边界（reference §5.5）。

### 阶段 6　归档收尾

- 报告 + 截图归档到项目约定位置（见 reference §7.2）
- 临时环境清理；保留的桥接进程在报告中说明
- 收尾核验各仓 `git status` 干净（只留预期新文件）
- 测试数据登记，由用户决定是否清理

## 高频陷阱（Top 10，全表见 reference §8）

| # | 现象 | 对策 |
| --- | --- | --- |
| 1 | 端口 TCP 通但 HTTP 被 reset | 残留转发占用，勿反复重试 |
| 2 | 浏览器访问 `127.0.0.1` 报 `ERR_CONNECTION_REFUSED` | 浏览器在容器内，改用桥接或宿主 IP |
| 3 | 心算 MOCK 验证码算错 | 一律查库核对 |
| 4 | 快照里自定义组件选项为空 | 回落 `role="option"` DOM 查询 |
| 5 | 连续点多个选项只生效一个 | 一次调用只点一个 |
| 6 | 提示消息抓不到 | 触发前预埋 MutationObserver |
| 7 | 负例全返同一错误码 | 先跑正例基准 |
| 8 | 契约字段格式与实现不符 | 以真实请求体为准 |
| 9 | dbx 报 `Unknown column` | 先 `describe_table` |
| 10 | 私有桶 403 误判为失败 | 403=存在，404=不存在 |

## 验收与勾选口径

- 冒烟通过 = 用例矩阵无失败项 + 三层证据齐全 + 工作区洁净
- 验收描述含"真机/真实组件"字样 → 必须走真实外部组件，MOCK 通过不算
- 验收依赖未实现能力 → 标 N/A 并给等效证据，不得含糊略过
- 观察项单列，写明影响面与建议归属
