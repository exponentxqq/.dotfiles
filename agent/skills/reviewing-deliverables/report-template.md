# 交付审核报告模板

> 按此结构生成报告，写入 `<交付目录>/delivery-review-report.md`（简体中文）。
> 检查项汇总表必须列出**全部**检查项（含通过项）；问题详情只列不通过项。
> 无问题的级别区块可省略；无跳过文件时「审核范围」表仍要列出全部已审文件。

---

```markdown
# 交付审核报告

- **审核时间**：YYYY-MM-DD HH:MM
- **交付目录**：`<绝对路径>`
- **依据来源**：<本次对话要求 / DELIVERY.md / 内置 checklist>（列出实际生效的层级）
- **文件总数**：N（已审 M / 跳过 K）
- **结论**：✅ 通过 | ⚠️ 有条件通过 | ❌ 不通过

## 检查项汇总

| # | 检查项 | 适用类型 | 结果 | 问题数 |
|---|---|---|---|---|
| 1 | 清单承诺 ≠ 实物 | 全部 | ❌ | 1 |
| 2 | 占位符未替换 | 全部 | ❌ | 3 |
| 3 | 敏感信息 | 全部 | ❌ | 2 |
| 4 | 错别字 | 全部 | ✅ | - |
| … | （按 checklist 逐项列出，不遗漏） | | | |

## 问题详情

> 每条必须包含：文件、描述、证据、修复建议

### Blocker（N）

#### B1 <一句话标题>
- **文件**：`path/to/file(:line)`
- **描述**：…
- **证据**：<原文引用 / 图片问题描述 / 截图位置>
- **建议**：…

### Major（N）

#### M1 <一句话标题>
- **文件**：…
- **描述**：…
- **证据**：…
- **建议**：…

### Minor（N）

#### m1 <一句话标题>
- **文件**：…
- **描述**：…
- **证据**：…
- **建议**：…

## 结论说明

<结论判定依据：Blocker 数 / Major 数；若为「有条件通过」，列出交付前必须解决项>

## 审核范围

| 文件 | 状态 |
|---|---|
| 方案书.md | 已审 |
| screenshot-1.png | 已审（vision） |
| code/archive.zip | 跳过（压缩包，未展开） |

> ⚠️ 本报告 `delivery-review-report.md` 为内部审核产物，打包交付前请排除。
```
