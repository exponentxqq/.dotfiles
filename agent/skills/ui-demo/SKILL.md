# 界面演示（ui-demo）

**演示是确认工具，不是交付物。** 本 skill 是判定、分级、产物规范与自检序列的唯一权威源；其他手册只引用不复述。

## 核心原则

1. **没有图就先给看**：无设计稿的界面需求，动手写实现之前必须先产出可打开的演示页。
2. **未确认不得落实现**：用户对视觉与布局给出明确确认（或书面豁免）之前，禁止写业务实现代码、禁止落档；「你看着办」不是确认，恰是触发条件。
3. **演示 ≠ 最终实现**：演示页顶部必须写明「界面演示，非最终实现」；演示通过不等于实现通过。
4. **布局自带可读性**：删掉多余的标语、说明文字和次要标签。如果删完界面就看不懂，说明布局本身就有问题，直接重新设计。

## 何时触发（判定）

**判定式**：`C1 ∧ C2 ∧ C3` 同时成立，且不命中下方排除表任一行 → 进入演示；否则记录未触发。

- **C1 界面产出**：需求涉及页面、组件、弹窗、表单、仪表盘、移动端页面、布局或视觉改版、交互流程的可视化。
- **C2 无设计依据**：用户未提供 Figma 链接、截图、原型图，也没有既有页面可照抄（含「我没设计稿，你看着办」这类授权）。
- **C3 须自定视觉与布局**：不是纯逻辑/后端/数据/配置改动；也不是在既有设计体系内做零视觉决策的机械改动（加一个字段、加一个接口）。

| 排除行 | 判据 |
| --- | --- |
| 纯后端 / CLI / 数据迁移 / 配置 / 脚本 | C1 不成立 |
| 已有 Figma 链接、截图、原型图，或 figma MCP 可取到设计 | C2 不成立 |
| 仅文案、字号、颜色 token 的局部替换，或整体沿用既有设计系统且无新布局 | C3 不成立 |
| 用户明确要求「不用演示，直接做」 | 用户豁免（**必须留痕**） |
| 需求本身已是可交互原型/静态页（用户在给的就是成品视觉） | C2 不成立 |

未命中必须在留痕处记一行 `1.75 未触发：<哪条不成立或命中哪行排除表>`——一行也必须有。

## 产出分级

按**语义判据**分档，命中即升档、取最高档；**L1 是默认档**（无命中即 L1），不是「最简档」。

| 档 | 语义判据 | 必须包含（逐项清单见 refs） |
| --- | --- | --- |
| **L1**（默认） | 单屏静态布局，无关键交互流转 | 主要区域划分、信息层级、关键控件与其位置、字号/间距/圆角基调、配色方案（≤3 主色 + 中性色阶）、空态占位说明 |
| **L2** | 含关键交互流或多状态（打开/关闭、提交中、校验失败、空/加载/错误、步骤流转） | L1 全部 + 每个状态一屏（同页多 section 或 tab 切换）、按钮禁用/悬停态、错误提示文案位 |
| **L3** | 视觉方向完全开放且用户未给偏好（无品牌/设计系统可依，或用户明说「你定」） | 2–3 个方向不同的方案（单文件内）：**以顶部 tab 切换为主，每方向独占视口宽**，每方案一句设计意图 + 取舍；并排缩略仅在用户显式要求一屏对比时使用；用户先选方向再细化到 L1/L2 |

- **L2/L3 同时命中 → 按 L3 交付**：多方向并列，各方向按 L2 深度。
- **不设数值化 checklist**：状态数、色数等数值只作「拿不准时向上取档」的提示，不作判据。
- 各档逐项元素清单与三套 section 模板在 [refs/html-recipe.md](refs/html-recipe.md)，写页前读。

## 产物规范

**路径矩阵**

| 场景 | 生成期路径（易失） | 落位路径（入库） |
| --- | --- | --- |
| spec-plan 阶段 1.75 | `/tmp/spec-flow/<change>/demos/<slug>.html` | `openspec/changes/<change>/demos/<slug>.html`（落档复制） |
| openspec explore / propose（变更目录已存在） | 直接写 `openspec/changes/<change>/demos/<slug>.html` | 同左 |
| openspec explore（变更目录未建） | `/tmp/spec-flow/<change>/demos/<slug>.html` | 建 `openspec/changes/<change>/demos/` 后迁入，并告知最终位置 |
| `/plan`（不经 openspec） | `/tmp/ui-demos/<change>/<slug>.html` | **不入库：即确认即弃** |

`slug` = kebab-case、描述场景而非编号（`login-captcha-l1.html`、`dashboard-l3-directions.html`）；同变更多档用 `-l1/-l2/-l3` 后缀。

**HTML 契约（可机械核对）**

1. **单文件自包含**：样式内联 `<style>`，**零外部请求**（禁 CDN、禁 webfont 外链、禁 `<img src="http…">`）；图标用 inline SVG 或 Unicode。
2. **禁 base64 大图**（单张 >20KB 一律用 CSS 形状/SVG 代替）；单文件 **≤100 000 字节**。
3. `<meta name="viewport" content="width=device-width, initial-scale=1">`；桌面（≥1280px）与窄屏（≤480px）均不横向滚动。
4. 顶部固定**演示约束条**（一个 `<header>`）：`变更名 · 分档 Lx · 生成时间 · 「界面演示，非最终实现」`。
5. 交互用按钮 + 纯 CSS `:target`/`:checked`/`details` 或 ≤50 行内联 JS 切换**假状态**；不连后端、不发请求。
6. 语义标签（`<header>/<main>/<section>/<button>`）与可读对比度（正文与背景 ≥ 4.5:1）。
7. **假数据必须标注「示意数据」**（列表、图表、统计数字旁一句即可）。

**预览（file:// 直开）**

- 容器内自检：`file:///tmp/spec-flow/<change>/demos/<slug>.html`
- 宿主给用户：**`file:///data/tmp/spec-flow/<change>/demos/<slug>.html`**（容器 `/tmp` ≡ 宿主 `/data/tmp`）
- `/plan` 场景：容器 `file:///tmp/ui-demos/<change>/<slug>.html`；宿主 `file:///data/tmp/ui-demos/<change>/<slug>.html`（即确认即弃）
- 落档后：`file:///home/xuqinqin/develop/<repo>/openspec/changes/<change>/demos/<slug>.html`
- nginx 统一入口（如 `ui-demos.localhost`）不在本能力内实现——只留扩展位：未来接入时上述路径约定不变。

## 自检

交付用户前，用 **chrome-shared** MCP（chrome-devtools 工具集）对 `file://` 新标签页自检（URL 按第 4 节路径矩阵取实际产物路径）：

1. `new_page(url=file:///tmp/spec-flow/<change>/demos/<slug>.html)` —— **必须新标签页**（共享浏览器多会话隔离）。
2. `take_screenshot(pageId, fullPage=true)` —— 核对：约束条在顶、无空白区块、无横向溢出、无多余标语/说明/次要标签；一屏不足再分段。
3. `list_console_messages(pageId)` —— 断言无 `error`、无 `Failed to load resource`（外链残留的硬信号）。
4. `close_page(pageId)` —— 不留标签页给别人。

视口至少验两种：默认（1440×900 级）与 `resize_page(width=390, height=844)`；窄屏只截图核对，不 `emulate` 设备。多 tab / 多状态逐一切换各验一次。

chrome-shared MCP 不可用（`new_page` 报错或工具未接入）时按表降级，并在确认留痕里声明证据缺口：

| 缺失 | 降级方式 | 证据缺口 |
| --- | --- | --- |
| chrome-shared MCP | 如实告知用户「未做渲染自检」，给宿主 `file:///data/tmp/...` 路径请其自行打开并截图回传 | **UI 自检证据缺失** |

降级结论必须标注**「未做渲染自检」**，不得宣称自检通过。截图属证据，落 `/tmp/spec-flow/<change>/` 或直接丢弃；**演示 HTML 落库、截图不落库**。

自检通过后交用户，一次问清：`①确认，转入下一步　②要改：<具体点>　③降档/豁免（写明依据）`；未取得确认不得视为通过。

## 三处入口接线

| 入口 | 接线强度 | 触发时产物落点 | 留痕位置 |
| --- | --- | --- | --- |
| spec-plan 阶段 1.75 | **硬 gate**（未确认不得落档） | `/tmp/spec-flow/<change>/demos/` → 落档复制入变更目录 | `code-design.md` 附录 → `design.md` 决策记录 |
| openspec explore / propose | **软**（frontmatter 触发词 + 本 skill 接线规则） | 变更目录在则 `<change>/demos/`；否则 `/tmp/spec-flow/<change>/demos/` 再迁入 | 会话产出 + 对话摘要；有 code-design 时同左 |
| `/plan` 规划模式 | **软**（同上；plan 无手册可改） | `/tmp/ui-demos/<change>/<slug>.html`（即确认即弃） | 计划文件末「界面演示」一行（路径 + 确认状态） |

**软接线不宣称强制**：命中率取决于本 skill 的 `description` 是否被读成「界面设计且无设计稿」——这是已接受的残余风险，回执里不得写成「必然触发」。

## 常见错误

| 错误做法 | 为什么错 | 正确做法 |
| --- | --- | --- |
| 先写实现，事后补演示 | 演示是确认工具；事后补等于先斩后奏，返工成本最高 | 命中判定即停手，先出演示再写实现 |
| 把演示当最终实现 | 演示只确认视觉与布局，不含真实数据与后端逻辑 | 顶部写明「非最终实现」，确认后另行实现 |
| 把 base64 大图内联 | 单页可达 MB 级，入库后永久留在 git 历史 | 大图用 CSS 形状/SVG 代替，单文件 ≤100 000 字节 |
| 用 `localStorage`/fetch 造数据 | 演示须零外部请求、状态可复现；接接口或持久化会引入环境依赖与残留状态 | 假数据写死在页内，并标注「示意数据」 |
| 不写分档 | 不分档就不知道出几屏、要不要多方向，确认会反复 | 先按 L1/L2/L3 判档，档位写进约束条 |
| 未确认就落档或继续实现 | 硬 gate 的意义就是确认前置；未确认落档 = 契约锁死错误方向 | 三选一确认（确认 / 要改 / 降档或豁免）后才继续 |
| 靠标语、说明文字、次要标签撑可读性 | 删掉这些文案就看不懂 = 可读性来自文案而非布局，用户确认的是文案不是布局 | 删掉多余文案；删完看不懂直接重新设计布局，不加回文案 |
