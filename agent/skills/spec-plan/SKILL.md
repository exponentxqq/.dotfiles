# spec-plan 规划半程

本 skill 是**执行手册**：每步按本文执行，未写到的情况回到用户。本文件面向**没有本次对话上下文**的未来会话——一切从工件与命令输出重建。

## 一、总览

规划四阶段流水线，入口为用户级命令 `/spec-plan`，或被 `spec-workflow` 委托作为其阶段 1→2（参数转发、已预置不重问）：

```
阶段1 独立双线规划 → 阶段1.5 差异收敛与分歧复算 → 阶段1.7 代码设计 → 阶段2 落档（终于落档提交）
line-a + line-b  diff-matrix + 第三线复算  code-design.md  openspec-propose 四件套 + 工件单独提交
```

**本流程到落档提交为止**：不写项目代码、不涉及执行模式、不派执行子代理；收尾固定告知 `/spec-flow continue <变更名>` 接续执行（委托场景由 spec-workflow 无缝衔接：确认执行模式与引擎后继续）。

**状态载体 = 工件**：`/tmp/spec-flow/<change>/` 规划材料易失、不入库、不进提交；落档提交后的权威进度 = 变更工件 + git 提交。

承诺：**阶段边界必汇报**、**规划外 scope 变化回到用户**、**不假设未给出的选项**。

参数（**一次只问该阶段需要的，已预置的不再问**；委托转发来的参数视同已预置）：

| 参数 | 取值与缺省（含询问时机） |
| --- | --- |
| `<需求描述>` | 需求原文；为空则问「要做什么」 |
| `--parallel` | 两线各派一个 fresh 子代理并行独立完成；缺省串行，阶段 1 前未给则问 |
| `--model <阶段>=<provider>/<模型>` | 规划键（lineA/lineB/panel/design）模型覆盖；缺省读映射文件（第八节） |

展开内容按**消费时机**外移到 **`refs/`**（按下表按需读取，读到的与正文同等权威）：

| 消费时机 | 读什么 |
| --- | --- |
| 阶段 1 派发规划线前 | [planning.md](refs/planning.md) —— 派发模板、回执核对、前置检查展开、落档细节 |
| 阶段 1.5 | [convergence.md](refs/convergence.md) —— 设计树/前沿分轮与六步判据 |
| 派发子代理前 | [routing.md](refs/routing.md) —— 规划键路由、三档回退、白名单、图片能力、自检 |
| 异常、边界、失败 | [failure-modes.md](refs/failure-modes.md) —— 处置表主体（红线见第九节） |

**压缩后恢复速查**（红线级）：规划材料易失——中断后重进，从 `/tmp/spec-flow/<change>/` 已有材料与阶段摘要重建，缺失即重做对应阶段并如实告知；**绝不把待决项静默变成假设**。

## 二、前置检查

开工前五项（展开见 [planning.md](refs/planning.md)）：**①OpenSpec 根**（`openspec list --json` 读 `root`；`null` → 未接入：**绝不副作用创建** `openspec/`，问 init / store / 放弃）｜**②参数**（需求原文 / 并行 / 模型覆盖）｜**③工作目录事实**（含 `git status --porcelain`；无关脏改动**不擅自 stash / commit / revert**）｜**④能力自检**（`openspec-propose` 与阶段 1.5 所需 `grill-me`；`grill-me` 缺失时降级为普通按轮提问并如实告知）｜**⑤路由自检**（派发子代理前，按 [routing.md](refs/routing.md) 三档回退）。

## 三、模式收集

**唯一规则：一次只问该阶段需要的选项，已由参数预置的不再问，绝不自行假设。**答复写进阶段摘要（变更名、编排、模型覆盖）。

## 四、阶段 1 独立双线规划（异构视角，非分工）

两条**方向不同、各自完整**的规划线，**不是分工**：两种视角各自把需求**完整**规划一遍，让盲区在阶段 1.5 交叉比对中互相暴露。

**A 线**（需求与价值、范围与边界——要解决什么、为谁解决、边界在哪）与 **B 线**（实现与约束、反例与风险——怎么做、会怎么错、代价是什么）；产物分别落 `/tmp/spec-flow/<change>/line-a.md`、`line-b.md`。

**每条线都产出同一套字段的完整轻量规划草案**——7 项**不得缺项、不得合并、不得只写本方向内的那几项**（目标与非目标 / 范围与边界 / 方案与取舍 / 任务拆分 / 验证思路 / 风险与未知 / 假设清单）；两线**结构与完备度完全一致**。

### 独立性铁律（核心价值，不得打折）

- **不得读取对方产物**：不读取、不检索、不引用另一条线的 `line-*.md`。
- **不得共享中间结论**：不得把一条线的结论"顺口"带进另一条线的提示。
- **不得跳过"另一条线负责的部分"**：凡影响方案走向的内容本线自己写。
- **信息不足时自行查证或上浮**：查不到的写进「假设清单」「风险与未知」；**需用户拍板的不得自行假设**。
- **两条线的提示除「方向」外完全等形**。

### 待决问题的中转交互协议（子代理 ↔ 用户）

**平台事实**：被父代理拥有的子代理**不能直接向用户提问**——调用提问工具被 `DELEGATED_CALLER` 拒绝（team 的 teammate 同受此限）。**这是平台设计，不是故障**。协议适用于规划线、复算线、设计线：

1. **① 上浮**：决策**不得自行假设**；写进产物「待决问题」节（**问题、选项、推荐、影响面**）并列回执 TOP 项后结束回合；**不得为等答复阻塞、空转、轮询**。
2. **② 代问**：主会话**立即**代问，**不积压、不另开通道**——规划线上浮项**并入阶段 1.5 统一提问**；设计线（阶段 1.7）上浮项**并入落档分歧点提问**。
3. **③ 记录**：规划期写 `diff-matrix.md`；设计期并入落档分歧点。
4. **④ 回送**：**team** 用 `send_message` 回**同一成员**；**subagent** 以上轮回执摘要 + 答复**接续重派**（**非同一实例**）。
5. **⑤ 终止**：待决项清空，或用户授权**「按假设清单推进」**（标注**「已授权的假设清单」**）。

**两条禁令**：**不得把待决项静默变成假设**；**不得让子代理为等答复而阻塞或轮询**。

派发细节（并行/串行模板、串行独立性注记、回执核对）见 [planning.md](refs/planning.md)。

## 五、差异收敛与分歧复算（阶段 1.5）

两线都回执后做差异收敛——**六步，一步不省**；**第 4 步遵循 `grill-me` 的设计树/前沿分轮方法**（**问答由主会话执行**；判据与留痕见 [convergence.md](refs/convergence.md)）：

**①交叉比对**（**共识** / **分歧** / **单边遗漏**；单边项 SHALL **逐项核验**，**绝不因"只有一条线提出"而丢弃**）→ **②自行裁定**（能查证的自己查证，**不得转为提问**）→ **③分歧复算**（无法查证的派第三条 **fresh** 子代理；三条互异 → **用户决策项**；**最多 3 个**）→ **④问决策项**（设计树**只问前沿**、每轮 **≤5 问**、附**推荐与来源**）→ **⑤记录**（`/tmp/spec-flow/<change>/diff-matrix.md`）→ **⑥收敛结束**（**前沿为空**或用户**确认「已达成共识 / 可以落档」**；未答项**不得静默假设**）。

**只问决策，不问事实**。

## 六、代码设计（阶段 1.7）

1.5 收敛后、落档前：**恒派 fresh 子代理**（`design` 路由，不随阶段 1 编排模式变化）产出 `code-design.md`——深度契约**六字段**（触达面清单 / 证据锚 / 接口与数据形状 / 决策记录 / 逐任务组实现要点 / 设计假设与未决项）+ **二行为约束**，**三档分降** L2/L1/L0（trivial 豁免派遣、inline 一行断言落档）。**派发前主会话做栈识别**，设计子代理**须先加载栈对应 writer skill**（未命中问用户三选一，**不静默跳过**）；**栈识别结论（writer 名与证据）须写入落档 design.md 决策记录**——执行侧与接续恢复从工件读取。模板、深度契约与回执核对见 [planning.md](refs/planning.md)『附：代码设计环节（阶段 1.7）』。

## 七、落档（阶段 2）

加载 `openspec-propose` skill 生成工件；输入 = 需求原文 + `line-a.md` + `line-b.md` + `diff-matrix.md` + `code-design.md`（缺后两者分别说明阶段 1.5 / 1.7 未做完）。细节见 [planning.md](refs/planning.md)『附：落档细节』：

**①四件套** → **②`tasks.md` 执行批次契约（硬约束）**：`## N. 组名` = 批次（**组即执行审核批次**，组内单任务合法、分组兼顾用户审核节奏）、**组间串行**、**组内可并行**、**验证句必须第三方可核对**、单组 ≤ `parallelism` → **③分歧点提问** → **④`openspec validate <change> --strict` 退出码 0**（不得带病落档）→ **⑤落档即停** → **⑥展示摘要** → **⑦工件单独提交一次** → **⑧固定收尾**：告知 `/spec-flow continue <change>` 随时接续执行。

## 八、模型路由

映射文件 **`/home/xuqinqin/develop/dotfiles/dsh/spec-workflow.yaml`**（**绝对**路径）：规划键 `lineA`/`lineB`/`panel`/`design` → 阶段 1 A/B 线、1.5 复算线、1.7 设计线；能力键 `vision` = **读图覆盖**。执行键（`apply`/`verify`）、`engine` 由 spec-workflow 消费；`parallelism` 用于第七节分组上限。**优先级：`--model` > 映射文件 > 继承会话模型。**

红线要点（**展开唯一权威源 = [routing.md](refs/routing.md)——派发前先读它**）：**三档回退**（顺序固定，不反复重试）——①有 `fallback` → 备用**重派一次**；②无或备用也失败 → **回退继承会话模型**一次；③仍失败 → 报告并暂停。**读图**——`zai/glm-5.3` **不支持图片**，`does not declare image input` 是**能力事实不是故障** → 改走 `vision`。

## 九、边界与失败

**红线级条目**（违反即致不可逆、失控或静默假设）；其余异常与失败处置见 [failure-modes.md](refs/failure-modes.md)，**遇异常先读它**：

| 情形 | 处置 |
| --- | --- |
| 无 openspec 根（`root: null`） | 问 init / store / 放弃，**绝不副作用创建** `openspec/`（第二节） |
| 子代理需用户决策 / 直接提问被拒（`DELEGATED_CALLER`） | 走第四节中转协议：上浮 → 主会话**立即代问** → team 回送**同一成员**、subagent 接续重派。**`DELEGATED_CALLER` 是平台设计，不是故障**——不判定工具损坏、不重试直接提问 |
| 设计草案与收敛结论矛盾 | 上浮待决并入落档分歧点提问，**不重开收敛**（第六节） |

**绝不做**：不自行 `openspec init`；不在落档后继续执行或选择执行模式；不动目标项目的 CI、密钥、生产配置；不把子代理上浮的待决项**静默变成假设**；不把 `/tmp/spec-flow/` 的临时材料当作超出落档输入的进度承诺；工件未过 `--strict` 校验不提交。
