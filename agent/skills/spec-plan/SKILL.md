# spec-plan 规划半程

本 skill 是**执行手册**：每步按本文执行，未写到的情况回到用户。本文件面向**没有本次对话上下文**的未来会话——一切从工件与命令输出重建。

## 一、总览

规划四阶段流水线，入口为用户级命令 `/spec-plan`，或被 `spec-workflow` 编排委托作为其阶段 1→2（参数转发、已预置不重问）：

```
阶段1 规划编排 → 阶段1.5 收敛 → 阶段1.7 代码设计 → 阶段2 落档（终于落档提交）
并行=双线（team 驱动）  并行=七步（含审视）   code-design.md   四件套+两规划材料
串行=单线（explore）    串行=grill-me 直收
```

**本流程到落档提交为止**：不写项目代码、不涉及执行模式、不派执行子代理；收尾固定告知 `/spec-flow continue <变更名>` 接续执行（委托场景由 spec-workflow 衔接后委托 spec-apply 继续（模式/引擎由其承接））。

**状态载体 = 工件**：`/tmp/spec-flow/<change>/` 规划材料易失、不入库；**唯一例外——`code-design.md` 与 `diff-matrix.md`（串行 `decisions.md`）随落档复制入 `openspec/changes/<change>/`，落档后以落档副本为权威**（执行期维护与接续恢复读它）。产物命名辨编排：并行 `line-a.md`+`line-b.md`+`diff-matrix.md`；串行 `explore.md`+`decisions.md`。

承诺：**阶段边界必汇报**、**规划外 scope 变化回到用户**、**不假设未给出的选项**。

参数（**一次只问该阶段需要的，已预置的不再问**；委托转发来的参数视同已预置）：

| 参数 | 取值与缺省（含询问时机） |
| --- | --- |
| `<需求描述>` | 需求原文；为空则问「要做什么」 |
| `--parallel` | 并行编排：双线各自独立完成——默认 **team 驱动**（每线一个具名成员，`send_message` 同实例多轮澄清），不可行时**按线回退 subagent**（判据见 mode/parallel.md）；缺省**串行**（单线探索），阶段 1 前未给则问 |
| `--model <阶段>=<provider>/<模型>` | 规划键（lineA/lineB/panel/design）模型覆盖，**仅 subagent 派发时应用**；缺省读映射文件（第八节） |

展开内容按**消费时机**外移（按下表按需读取，读到的与正文同等权威）：

| 消费时机 | 读什么 |
| --- | --- |
| 阶段 1 开始前 | **按编排读其一**：[parallel.md](mode/parallel.md)（并行手册——team 派发、回退判据、模板、回执核对）或 [serial.md](mode/serial.md)（串行手册——explore 契约、grill-me 收敛） |
| 并行阶段 1.5 | [convergence.md](refs/convergence.md) —— 七步判据（含探索审视） |
| 派发子代理前 | [routing.md](refs/routing.md) —— 规划键路由、三档回退、白名单、图片能力、自检 |
| 阶段 1.7 / 落档 | [planning.md](refs/planning.md) —— 前置检查展开、设计契约、落档细节 |
| 异常、边界、失败 | [failure-modes.md](refs/failure-modes.md) —— 处置表主体（红线见第九节） |

**压缩后恢复速查**（红线级）：规划材料易失（落档入库的两材料除外）——中断后重进，按 `/tmp/spec-flow/<change>/` 现存文件名辨编排与阶段（`explore.md`/`decisions.md`=串行、`line-*.md`=并行），缺失即重做对应阶段并如实告知；落档后两材料从变更目录取；**绝不把待决项静默变成假设**。

## 二、前置检查

开工前五项（展开见 [planning.md](refs/planning.md)）：**①OpenSpec 根**（`openspec list --json` 读 `root`；`null` → 未接入：**绝不副作用创建** `openspec/`，问 init / store / 放弃）｜**②参数**（需求原文 / 并行 / 模型覆盖）｜**③工作目录事实**（含 `git status --porcelain`；无关脏改动**不擅自 stash / commit / revert**）｜**④能力自检**（`openspec-propose` 与阶段 1.5 所需 `grill-me`；**串行阶段 1 与并行审视段另需 `openspec-explore`**——缺失按 [failure-modes.md](refs/failure-modes.md) 修复后问用户，**不静默降级**；`grill-me` 缺失时降级为普通按轮提问并如实告知）｜**⑤路由自检**（派发子代理前，按 [routing.md](refs/routing.md) 三档回退）。

## 三、模式收集

**唯一规则：一次只问该阶段需要的选项，已由参数预置的不再问，绝不自行假设。**答复写进阶段摘要（变更名、编排、每线引擎、模型覆盖、回退原因）。

## 四、阶段 1 规划编排（并行双线 / 串行单线）

**并行（`--parallel`）**：两条**方向不同、各自完整**的规划线，**不是分工**——**A 线**（需求与价值、范围与边界——要解决什么、为谁解决、边界在哪）与 **B 线**（实现与约束、反例与风险——怎么做、会怎么错、代价是什么）各自把需求**完整**规划一遍，让盲区在阶段 1.5 交叉比对中互相暴露；产物 `line-a.md`/`line-b.md`。**派发默认 team 驱动**：每线一个具名 fresh 成员（`spawn_teammate`），不可行时按线回退 subagent；每条线产出**同一套 7 字段**的完整轻量草案（目标与非目标 / 范围与边界 / 方案与取舍 / 任务拆分 / 验证思路 / 风险与未知 / 假设清单），两线结构与完备度完全一致。

**串行（缺省）**：**单线**——主会话加载 `openspec-explore` 探索并产出单份 7 字段草案 `explore.md`（另立待决问题节），**不产第二条线**；待决项留阶段 1.5 收敛。

### 独立性铁律（并行核心价值，不得打折）

- **不得读取对方产物**：不读取、不检索、不引用另一条线的 `line-*.md`。
- **不得共享中间结论**：不得把一条线的结论"顺口"带进另一条线的提示。
- **不得跳过"另一条线负责的部分"**：凡影响方案走向的内容本线自己写。
- **信息不足时自行查证或上浮**：查不到的写进「假设清单」「风险与未知」；**需用户拍板的不得自行假设**。
- **两条线的提示除「方向」外完全等形**。

### 待决问题的中转交互协议（成员/子代理 ↔ 用户）

**适用范围**：并行规划线、复算线与阶段 1.7 设计线（team 成员与被拥有的子代理同受此限）；**串行单线由主会话直问用户，不经中转**。

**平台事实**：被父代理拥有的子代理**不能直接向用户提问**——调用提问工具被 `DELEGATED_CALLER` 拒绝。**这是平台设计，不是故障**。协议：

1. **① 上浮**：决策**不得自行假设**；写进产物「待决问题」节（**问题、选项、推荐、影响面**）并列回执 TOP 项后结束回合；**不得为等答复阻塞、空转、轮询**。
2. **② 代问**：主会话**立即**代问，**不积压、不另开通道**——并行规划线上浮项**并入阶段 1.5 统一提问**；设计线（阶段 1.7）上浮项**并入落档分歧点提问**。
3. **③ 记录**：并行期写 `diff-matrix.md`；设计期并入落档分歧点。
4. **④ 回送**：**team** 用 `send_message` 回**同一成员**（同实例多轮）；**subagent** 以上轮回执摘要 + 答复**接续重派**（**非同一实例**）。
5. **⑤ 终止**：待决项清空，或用户授权**「按假设清单推进」**（标注**「已授权的假设清单」**）。

**两条禁令**：**不得把待决项静默变成假设**；**不得让子代理为等答复而阻塞或轮询**。

派发细节（team 成员规约与 5 条回退判据、subagent 并行模板、回执核对）见 [parallel.md](mode/parallel.md)；串行探索契约与收敛接线见 [serial.md](mode/serial.md)。

## 五、收敛与分歧复算（阶段 1.5）

**并行**：两线都回执后七步，一步不省（判据与留痕见 [convergence.md](refs/convergence.md)）：**①交叉比对**（共识 / 分歧 / 单边遗漏；单边项 SHALL **逐项核验**，**绝不因"只有一条线提出"而丢弃**）→ **②自行裁定**（能查证的自己查证，**不得转为提问**）→ **③分歧复算**（无法查证的派第三条 **fresh** 子代理；三条互异 → **用户决策项**；**最多 3 个**）→ **④探索审视**（加载 `openspec-explore` 审合并视图：补**双边盲区**、把可查证待决项降级为事实裁定；**不重开双线调研、不推翻已收敛共识**）→ **⑤问决策项**（`grill-me` 设计树**只问前沿**、每轮 **≤5 问**、附**推荐与来源**）→ **⑥记录**（`diff-matrix.md`）→ **⑦收敛结束**（**前沿为空**或用户确认「已达成共识 / 可以落档」；未答项**不得静默假设**）。

**串行**：跳过①–④——按 [serial.md](mode/serial.md) 以 `grill-me` 前沿分轮直接收敛 `explore.md` 待决项，留痕 `decisions.md`。

**只问决策，不问事实。**

## 六、代码设计（阶段 1.7）

1.5 收敛后、落档前：**恒派 fresh 子代理**（`design` 路由，不随阶段 1 编排模式变化）产出 `code-design.md`——深度契约**六字段**（触达面清单——**逐条注明所属仓** / 证据锚 / 接口与数据形状 / 决策记录 / 逐任务组实现要点 / 设计假设与未决项）+ **二行为约束**，**三档分降** L2/L1/L0（trivial 豁免派遣、inline 一行断言落档）。**派发前主会话做栈识别**，设计子代理**须先加载栈对应 writer skill**（未命中问用户三选一，**不静默跳过**）；**栈识别结论（writer 名与证据）须写入落档 design.md 决策记录**——执行侧与接续恢复从工件读取。**输入材料按编排**：并行 = 需求原文+`line-a.md`+`line-b.md`+`diff-matrix.md`；串行 = 需求原文+`explore.md`+`decisions.md`。模板、深度契约与回执核对见 [planning.md](refs/planning.md)『附：代码设计环节（阶段 1.7）』。

## 七、落档（阶段 2）

加载 `openspec-propose` skill 生成工件；输入 = 需求原文 + 并行（`line-a.md`+`line-b.md`+`diff-matrix.md`）/ 串行（`explore.md`+`decisions.md`）+ `code-design.md`（缺收敛留痕说明阶段 1.5 未做完、缺设计草案说明阶段 1.7 未做完——先补做再落档）。细节见 [planning.md](refs/planning.md)『附：落档细节』：

**①四件套 + 两份规划材料**（`code-design.md` 与 `diff-matrix.md`/串行 `decisions.md` **复制入变更目录**，落档副本自此为权威）→ **②`tasks.md` 执行批次契约（硬约束）**：`## N. 组名` = 执行审核批次、**组间串行**、**组内可并行**、验证句第三方可核对、单组 ≤ `parallelism` → **③分歧点提问** → **④两材料断言 + `openspec validate <change> --strict` 退出码 0**（`code-design.md` 与 `diff-matrix.md`/串行 `decisions.md` 须 `test -f` 在变更目录，断言展开见 [planning.md](refs/planning.md)；不得带病落档）→ **⑤落档即停** → **⑥展示摘要** → **⑦工件单独提交一次**（含两材料）→ **⑧固定收尾**：告知 `/spec-flow continue <change>` 随时接续执行。

## 八、模型路由

映射文件 **`/home/xuqinqin/develop/dotfiles/dsh/spec-workflow.yaml`**（**绝对**路径）：规划键 `lineA`/`lineB`/`panel`/`design` → 阶段 1 A/B 线、1.5 复算线、1.7 设计线；能力键 `vision` = **读图覆盖**。**路由仅适用于 subagent 派发**：**team 成员无模型参数**——team 编排下 `lineA`/`lineB` **不应用**（留痕告知）；**串行单线无派发，规划键不消费**；`panel`/`design` 恒为 subagent 派发，不受编排影响；**显式 `--model lineA|lineB` → 该线以 subagent 派发兑现路由**（不静默丢弃显式覆盖）。执行键（`apply`）、`engine`/`parallelism` 由 spec-apply 消费，`verify` 由 spec-done 复用；`parallelism` 用于第七节分组上限。**优先级：`--model` > 映射文件 > 继承会话模型。**

红线要点（**展开唯一权威源 = [routing.md](refs/routing.md)——派发前先读它**）：**三档回退**（顺序固定，不反复重试）——①有 `fallback` → 备用**重派一次**；②无或备用也失败 → **回退继承会话模型**一次；③仍失败 → 报告并暂停。**读图**——规划主路由 `deepseek-official/deepseek-flash`（V4.1 Flash，最新 1017）**支持图片**，正常直读；仅显式覆盖或 `fallback` 落到 `zai-coding-cn/glm-5.3` 等**不支持图片**的路由时，`does not declare image input` 是**能力事实不是故障** → 改走 `vision`。

## 九、边界与失败

**红线级条目**（违反即致不可逆、失控或静默假设）；其余异常与失败处置见 [failure-modes.md](refs/failure-modes.md)，**遇异常先读它**：

| 情形 | 处置 |
| --- | --- |
| 无 openspec 根（`root: null`） | 问 init / store / 放弃，**绝不副作用创建** `openspec/`（第二节） |
| 子代理/成员需用户决策、直接提问被拒（`DELEGATED_CALLER`） | 走第四节中转协议：上浮 → 主会话**立即代问** → team 回送**同一成员**、subagent 接续重派。**`DELEGATED_CALLER` 是平台设计，不是故障**——不判定工具损坏、不重试直接提问 |
| 设计草案与收敛结论矛盾 | 上浮待决并入落档分歧点提问，**不重开收敛**（第六节） |

**绝不做**：不自行 `openspec init`；不在落档后继续执行或选择执行模式；不动目标项目的 CI、密钥、生产配置；不把子代理上浮的待决项**静默变成假设**；不把 `/tmp/spec-flow/` 的临时材料当作超出落档输入的进度承诺（落档后以变更目录两材料为权威）；工件未过 `--strict` 校验不提交。
