## 串行模式（缺省，单线）

### 阶段 1：openspec-explore 单线探索

主会话**加载 `openspec-explore` skill**，借其探索纪律（**先查证后提问、跟随依赖展开、grounded 于代码事实、方案对比与取舍**）完成调研与规划：

1. **探索**：读代码、读 spec、跑只读命令，按需求依赖顺序展开（目标与边界 → 方案与取舍 → 任务拆分 → 风险）。**边界适配**：openspec-explore 的交接段（导向 `/openspec-propose`）**不适用**——落档由本 skill 阶段 2 控制，不跳转；其写前确认护栏不适用于 `/tmp` 规划材料（本流程自身行为，非 OpenSpec 工件写入）。
2. **产物契约（由本 skill 规定——openspec-explore 本身是 stance 无固定产物）**：落盘 `/tmp/spec-flow/<change>/explore.md`——同一套 **7 字段**的完整轻量草案（目标与非目标 / 范围与边界 / 方案与取舍 / 任务拆分 / 验证思路 / 风险与未知 / 假设清单），另立「待决问题」节（每条含 **问题 / 选项 / 推荐 / 影响面**；无待决项写「无」）。
3. **问答节奏**：零星澄清可即问（主会话可直问用户，无 `DELEGATED_CALLER` 限制）；系统性待决**汇聚到阶段 1.5** 分轮提问，防问答碎片化。
4. **不产第二条线**：串行没有并行双线的那对产物文件（无 line-* 命名），无独立性与复算议题；主会话**不得**再派规划成员/子代理。
5. **自查**（主会话自产，无重派语义）：`explore.md` 存在、7 字段齐备、待决节在——缺失即补写后再进 1.5；阶段摘要标注「串行单线」编排。

### 阶段 1.5：grill-me 前沿分轮收敛（decisions.md 留痕）

1. **映射设计树**：把 `explore.md` 待决节 + 探索中新产生的待决项映射为一棵设计树（**节点即决策、边即依赖**）。
2. **按 `grill-me` 分轮提问**：只问前沿、每轮 ≤5 问附推荐与来源、答完重算前沿；事实自行查证不问用户（必要时派只读子代理）；**跳过并行的交叉比对 / 自行裁定 / 分歧复算 / 探索审视四步——单线无对照源**（七步判据见 [../refs/convergence.md](../refs/convergence.md)，仅并行适用）。
3. **留痕**：`/tmp/spec-flow/<change>/decisions.md`——设计树、每轮问答（问题、答复、是否仍待决）、裁定依据与结论；它是阶段 2 落档输入之一，**落档时随 `explore.md` 流程复制入变更目录的是它**（见 SKILL.md 第七节；`explore.md` 本身不入库）。
4. **收敛结束**：前沿为空，或用户明确确认「已达成共识 / 可以落档」；未答项**不得静默假设**——写进落档 design 的「未决/后续」并列入落档摘要。

### openspec-explore 不可加载

按 [../refs/failure-modes.md](../refs/failure-modes.md) 处置顺序修复（聚合层与 skctl 登记核对 → `/commands-reload` → 重启兜底）；仍失败**报告问用户三选一**：①降级裸调研（不加载 skill，主会话按本文件产物契约自做，如实标注）②改并行编排重进 ③终止流程——**不静默降级**。
