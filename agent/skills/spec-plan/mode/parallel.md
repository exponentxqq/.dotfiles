## 并行模式（`--parallel`，team 驱动为默认）

### 引擎判定（每线独立：优先 team，命中任一判据即该线回退 subagent）

**team 派发**（Agent Teams 可用时）：在**同一条消息**内 `spawn_teammate` 创建两个具名成员，两线并行执行——

- **命名**：`spec-plan-<change>-line-a` / `spec-plan-<change>-line-b`（kebab-case、会话内唯一）。
- **context: fresh**——不继承主会话历史（独立性铁律；需求原文随提示携带，见下方模板）。
- **等待与观察**：`list_agents` / `wait_agent`；**回执 = 成员结束回合时的最终回复**（含产物路径 + TOP 待决项）。

**不可行判据（命中任一 → 仅该线回退 subagent，阶段摘要留痕原因；不反复重试成员创建）**：

1. 会话未挂载 Agent Teams（Lead 无 `spawn_teammate` 等工具）或服务不可用；
2. `spawn_teammate` 报错或成员 provisioning 转为 `failed`——直接回退，不重试 spawn；
3. 成员上限达限（`Team member limit 8 reached`——闲置成员也占名额）；
4. 成员卡死（长时间无回合进展）：`interrupt_agent` 中断后重建一次，仍不可用 → 该线回退 subagent；
5. 该线存在**显式** `--model lineA|lineB` 覆盖——成员无模型参数无法兑现，为不静默丢弃显式参数，该线以 subagent 派发并应用该路由。

**混合编排合法**：一线成员 + 一线子代理；每线引擎与回退原因写入阶段摘要。

**成员生命周期**：回执核对通过后成员转 idle——**不复用于**复算线（panel）或设计线（design）（保持 fresh 独立性）；正常完成**不 interrupt**；闲置成员持续占用 8 名额，若后续 spec-apply team 执行需成员，阶段摘要提示一句即可。

**team 下产物失败重派**：某线产物缺失 / 为空 / 答非所问 / 与另一线雷同 → `send_message` 要求**同一成员**补正一次（保留其上下文，不另建成员）；仍失败**如实报告**，由**用户决定**是否改派 subagent 重做该线或降级串行（**不得静默降级**）。

### 提示模板（自包含；两条线除「方向」与「引擎差异段」外逐字等形，缺一不可）

```
项目根（绝对路径）：<project root>
需求原文：<用户需求，逐字>
你的规划方向：<A：需求与价值、范围与边界——要解决什么、为谁解决、边界在哪
              | B：实现与约束、反例与风险——怎么做、会怎么错、代价是什么>
你的产物路径：/tmp/spec-flow/<change>/line-a.md   （B 线为 line-b.md）
产出要求：一份**完整的轻量规划草案**，下列 7 个字段**全部**写到、字段名照抄，不得缺项、不得合并、不得只写你方向内的那几项：
  1) 目标与非目标  2) 范围与边界  3) 方案与取舍  4) 任务拆分草案
  5) 验证思路      6) 风险与未知项  7) 假设清单
另立「待决问题」节（在 7 字段之外）：每条含 问题 / 选项 / 你的推荐 / 影响面；无待决项时写「无」。
事实自己查（读代码、读 spec、跑只读命令）；查不到的写进「假设清单」与「风险与未知项」。
引擎差异段（二选一）：
  - team 成员版：你是主会话（Lead）创建的具名团队成员，上下文独立、提示自包含；**最终回复即回执**。
  - subagent 版：以 `subagent` 工具派发 **fresh** 子代理（`run_in_background: true`；同一条消息内派发两线），**最终文本即回执**。
硬约束：
- 只允许写你自己的那一份产物文件；不得写项目文件、不得改 openspec/、不得 git add/commit。
- 不与用户直接交互：**你看不到用户、也不能提问**——被拥有的子代理/成员调用提问工具会被以错误码 `DELEGATED_CALLER` 拒绝。需要用户拍板的决策**不要自行假设**：写进产物「待决问题」节（每条含：**问题、选项、你的推荐、影响面**），并在**最终回复**中把它们列为本轮 TOP 待决项后结束回合——**不要为等答复而空转、阻塞或轮询**；主会话会代问用户并按引擎回送答复（见「待决问题的中转交互协议」）。
- 不得读取、引用另一条规划线的产物，也不得等待它。
```

**subagent 回退派发**：该线命中回退判据时，以 `subagent` 工具派发（模板引擎差异段取 subagent 版），并按 SKILL.md 第八节应用该线路由（`lineA`/`lineB`；需读图改 `vision`；三档回退见 [../refs/routing.md](../refs/routing.md)）。

### 回执核对（主会话必做，两引擎一致）

两份产物**都存在且非空** → 各读一遍，核对 7 字段是否齐备、能否明显看出两条线**方向上的差异**（两份草案结论雷同或字段残缺 → 独立性不成立，按失败处理）→ 输出 3–8 行阶段摘要（两线各自的关键判断、已可见的分歧点、单边遗漏信号、**每线引擎与回退原因**）作为阶段边界汇报；两线上浮的**待决问题按中转协议②并入阶段 1.5 的设计树/前沿统一提问**（不另开问答通道，不积压到阶段末）。某线失败的处置见上文「team 下产物失败重派」与 [../refs/failure-modes.md](../refs/failure-modes.md)。
