# Design

## Context

入口在第一步外移后为 15971 码点，仍超本部署宿主裁剪阈值（`dsh-compaction-tool-result-pruner`：8192 码点，超限 tool result 裁为头 4096 + 尾 1024）——`skill` 按名加载的返回仍会被裁剪。动机与机制事实链见 `proposal.md` Why 节与第一步归档记录。第一步已建立「按消费时机按需读取」的结构与验证方法（关键词唯一命中、逐字 diff、码点记录），本设计只解决入口总量达标与新增资源文件的形态。

## Goals / Non-Goals

**Goals:**

- 入口落 **[6800, 7830]** 码点，使渲染后 tool result ≤8192，`skill` 按名加载不再触发宿主裁剪
- 外移遵循同一原则：新增 `execution.md` / `convergence.md`，5 个资源文件各自 ≤8192 码点
- 12 节编号与标题逐字节不变、frontmatter 逐字节不变、主规格既有 Requirement 语义零变化
- 每批次可机器验证：语义等价断言 + 码点区间门 + 期望成品 md5 门

**Non-Goals:**

- 不改工作流语义：不删约束、不改触发条件、不增删阶段与步骤（骨架化 = 展开外移）
- 不改 `dsh/spec-workflow.yaml`、命令薄壳、其他 skill、dsh 平台实现
- 不做低于 6800 码点的极限压缩（触碰下限即停下复核，防过度削减）

## Decisions

### D1：外移映射（按消费时机）

| 现位置 | 码点量级 | 去向 | 消费时机 | 入口保留 |
| --- | --- | --- | --- | --- |
| §五 第 4 步 `grill-me` 设计树/前沿方法展开 | ~1100 | **→ `convergence.md`** | 阶段 1.5 开始 | 六步骨架 + 接线要点（≤5 问/轮、推荐来源标注、并入不另开通道） |
| §八 team 引擎细节 + subagent 提示模板/回执格式 | ~1200 | **→ `execution.md`** | 首次派发前 | 批次循环骨架 + 两引擎共同纪律 + 核对规则 |
| §六 `tasks.md` 批次契约展开 | ~500 | **→ `planning.md`** | 落档时 | 契约要点（分组=批次、组内独立、验证句可核对） |
| §二 store 接入异常分支 | ~500 | **→ `failure-modes.md`** | 遇到时 | 一行指针 |
| §四 中转协议展开（两档回送细节等） | ~1000 | **→ `planning.md`** | 派发前 | ①–⑤ 步名 + 两条禁令 + 平台事实一句话 |

### D2：去重清单（纯收益）

1. `DELEGATED_CALLER` 三处解释（§四 / §八 subagent 段 / §八 team 段 / §十二 红线表）→ 单一权威表述留 §四，其余改指针或一句话。
2. §一 参数面表与 §三 模式收集表 → 合并为一张（参数 + 缺省 + 询问时机）。
3. §十一 摘要内联的三档回退展开 → 收缩为「三档回退顺序」三行 + 指针（展开细节唯一权威源 = `routing.md`）。
4. §二 第 4/5 条的处置细节复述 → 收紧为「按 failure-modes.md / routing.md 处置」+ 关键数字（≤5 问/轮、parallelism、三档回退）。

### D3：红线内联最小集（不可外移，验收断言覆盖）

压缩后恢复速查、「绝不做」段、§十二 红线表、§七 六步恢复协议、§四 ①–⑤ 步名 + 两条禁令、独立性铁律、参数面合并表、按需读取路由表（措辞收窄为「仅 `subagent` 引擎派发前读 routing.md」，与 §二 第 5 条合并）。

### D4：资源文件布局与单文件上限

新增 `execution.md`、`convergence.md`；与既有 `routing.md`（3738）/ `failure-modes.md`（2169）/ `planning.md`（1590）共 5 件。单文件 ≤8192 码点写入生成规则（第一步官方先例反例：官方 `packages.md` 38768 码点会被裁）。

### D5：验证方法（复用第一步 + 新增硬线断言）

1. **码点门**：入口 `python3 len()` ∈ [6800, 7830]；每个 references ≤8192。
2. **渲染后实测**：会话内 `skill` 按名加载，实测完整返回码点 ≤8192（同时标定包裹开销常量，替代外部会话的 +360 估算）。
3. **语义等价**：外移内容与源逐字 diff 无输出；关键词唯一命中所属文件；12 节标题与 frontmatter 逐字节不变；`第十X节` 旧引用零残留；引用闭合全通过。
4. **确定性替换门**：入口改写落盘「期望成品」md5，成员执行后 `assert` 一致（复用第一步做法）。

### D6：备选与否决

- **中间态（~10000 码点）**：否决——仍触发裁剪，比例回升是分母效应，机制收益为零。
- **合并节（12 → 10）**：否决——全部「见第 X 节」交叉引用与外部 README 需重映射，风险大于收益。
- **全部并入现有三件**：否决——消费时机错位（执行引擎细节进失败处置文件），检索体验差。

## Risks / Trade-offs

- [改写量大导致语义漂移] → 纯剪切外移 + 逐字 diff；入口改写用确定性替换（期望成品 md5 门）；每批次停留审核；关键词唯一命中断言。
- [新资源文件被漏读] → 路由表收窄为「仅 subagent 引擎派发前读 routing.md」；执行/收敛指针写入对应节首；沿用第一步自举观察方法。
- [码点反弹或过度削减] → 每批次记录码点；超 7830 或低于 6800 即停下复核；余量约 1030 码点吸收渲染开销常量。
- [渲染后包裹开销未知] → 组 3 实测；若超阈值，用余量继续收紧（不牺牲红线最小集）。
