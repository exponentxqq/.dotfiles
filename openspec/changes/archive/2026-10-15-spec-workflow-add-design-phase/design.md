## Goals / Non-Goals

**Goals:**

- 代码设计深度获得结构保证：契约字段全部可第三方核对（路径、file:line、签名、命令）
- 设计-落档-执行三环贯通：设计草案 → design 继承 → 执行提示逐字引用
- 入口净零改写与主规格净增 ≤0（双硬门不回归）
- 产物 schema 恒定：design 恒在，下游（执行/验证/接续）零分支

**Non-Goals:**

- 不改阶段 1 双线轻量定位、不加码七字段
- 不改 openspec-propose / CLI 本体、不 fork design 模板
- 不新增用户参数（无 --no-design/--design）、不新增询问回合
- 不做双设计线、不动 convergence.md（1.5 判据）与 frontmatter

## Decisions

### D1 位置与编号：子阶段 1.7（pre-落档）

1.5 收敛后、落档前；复用 1.5 子阶段编号先例，零 12 节重排、零「见第 X 节」重映射（externalize-references D2 记录交叉引用密度：§十一被引 8 次）。**被否**：并入阶段 2 首步（「落档=写工件」语义膨胀，设计产物与落档中断状态纠缠）；post-落档 2.5（与「落档即停」「绝不重跑」两红线打架，接续多一个恢复状态）；重排顶层节（引用重映射风险大于收益）。

### D2 执行者：恒派 fresh 子代理 + 新路由键 `design`

不随阶段 1 编排模式变化（串行下主会话自做=自查自纠，B 线论证成立）。`design` 默认 `{ provider: zai, model: glm-5.3 }`（与规划三线同级强模型；白名单已含）。**被否**：复用 `panel`（污染「复算线」语义、统计不可辨）；不路由（放弃模型选择，主会话上下文已长）。

### D3 深度契约：内容六字段 + 行为二约束

内容：①触达面清单（逐文件路径+意图+关键改动点）②证据锚（每触达模块 ≥1 条 file:line，新建标「新建」）③接口与数据形状（签名/类型/配置键）④决策记录（附被否方案与理由 ≥1 反例）⑤逐任务组实现要点（与 tasks 分组对齐）⑥设计假设与未决项。行为：验证映射落具体命令或断言；不推翻 diff-matrix 结论（矛盾上浮不重开）。融合 A 线五字段与 B 线六断言（互补非冲突）。**被否**：纯章节名模板（深度沦为填空——契约必须锚定可核对物）。派发模板首行写死与双线的分界（双线=需求级轻重与风险；设计线=代码级蓝图），防与 line-b 复读。

### D4 小需求处置：恒跑 + 显式三档分降（复算 2:1 结论）

L2 全深度（默认）；L1 触达面 ≤2 文件且无新接口 → 字段③④⑤与验证映射允许单行简述（①⑥与二行为约束恒成立）；L0 trivial（单文件、无接口变更、无逻辑分支变化）→ 豁免 fresh 派遣，主会话 inline 一行断言落档，产物 schema 恒在。档位与判据落档 design.md。**被否**：`--no-design` 开关（schema 出现合法缺失态、分支复杂度转移下游、逃生口会被常态化滥用——A 线原案；其 trivial 成本关切被 L0 豁免内化）；默认关闭（多数调用回到旧缺口，需求名存实亡）；规模门自动跳过（「数触达面」恰是设计线产物，鸡生蛋）。

### D5 入口净零改写策略

SKILL.md 新增仅限：§一流水线图 +1 阶段、§五/§六间骨架句、§六输入清单 +1 材料句、§十一摘要键枚举 +design、§十一句澄清——预计 +200~300 码点，以等量收紧置换：§四串行模式细节外移、§一句式收紧（均为已外移内容的追加外移，逐字剪切方法成熟）。门：`len(SKILL.md) ∈ [6800, 7830]`（超上界即触发渲染裁剪、破下限需用户拍板）；frontmatter 逐字节不变；12 节标题不变。**被否**：下调 6800 下限（防过度削减的工程约定，仅在 a+b 不够时请用户拍板）；新建资源文件承载设计指令（路由表 +1 行加剧净零难度）。

### D6 主规格净增 ≤0

归档同步时收紧既有 Scenario 冗余措辞（「双线差异收敛」等节正文与 Scenario 重复度高，预计可回收 ≥500 码点），使 7914 + delta 净增 ≤0。**被否**：拆第二 capability（破「保持既有 capability 路径」惯例）；接受 >8192（把入口裁剪事故复制到规格层）。

### D7 上浮接线

1.7 上浮项并入落档第 3 步「分歧点提问」（planning.md:56 钩子已存在，加一句显式接线），不新开通道、不积压到落档后。

### D8 执行贯通：tasks 触达面硬契约 + 提示逐字引用

tasks 每任务引用触达面条目编号（「组内不写同一文件」机械化）；执行提示的「相关 spec/design 摘录」契约化为「design 该任务所属组实现要点逐字引用」。**被否**：建议性引用（无核对=无保证）。

### D9 指令正文位置：planning.md 新节

消费时机同为「规划期派发前」，零新增文件；planning.md 4496 → 预计 ~6200（<8192）。

## Risks / Trade-offs

- [入口净零改写失败（最险）] → 组内独立任务 + `python3 len()` 双门（写前预算、写后断言）+ 超上界即停；回退：§六落档细节追加外移
- [压缩 §四铁律时语义失真] → 红线相邻区逐字 diff、语义逐条比对后提交；候选段先写进 planning.md 再删入口（纯剪切）
- [主规格收紧回收不足] → 先逐句计数再动笔；不足则回落「接受 >8192 + 主规格瘦身另立变更」并请用户确认过渡风险
- [深度契约沦为填空] → 契约锚定可核对物（路径/file:line/签名/命令），核对步骤逐条 grep 式检查；设计线失败按规划线同构处置
- [propose 不忠实继承第 5 材料] → 回退：主会话按契约亲手写 design.md（不劣于现状）；自举冒烟实测
- [每变更 +1 轮派发成本] → L1/L0 降档；token 记录在执行日志供后续评估
- [L0 判据争议（「无逻辑分支变化」主观）] → 判据落档 design.md 可审计；阶段 4 核对不符回溯重跑
